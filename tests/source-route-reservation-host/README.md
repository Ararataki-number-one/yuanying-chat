This is an isolated **reservation design probe**, not Android qualification.
It compiles selected complete production NativeNetwork scheduling, stop and
clear-state methods, the actual ChatSession.runRecovery method, both actual
test-only start helpers, and the original terminal budget/admission methods.
`ReservationHost.SOURCE` is a fixed synthetic root-identity input copied from
the historical A2 source. It is not an installed build receipt. The runner's
separate Git HEAD, dirty flag and complete input hashes identify the actual
prototype files being compiled.

The main queue, private source preparation, transport, native startup IO and
session connection callback are explicit host adapters. They do not perform
Android Binder, Gecko, source encryption or network requests. A controlled clock
retains the literal 75-second and 22-second budgets without waiting 75 real
seconds. Real Java executors, waiters, futures and latches execute.
All six original contact-counter fields are modeled. Two negative controls
change controlled target/connection counters during preparation and return
either old or freshly replaced snapshots; both must be rejected. A successful
delegated startup after preparation failure deliberately increments those host
counters, so the raw side effects stay visible without claiming a real socket.
An unowned mode0 request is also appended through the actual `NativeNetwork.start`
method during preparation and during the delegated original body. Its real
callback must remain delivered while prototype qualification is rejected.

`verifyAccepted` establishes only the helper's preparation/ownership contract.
It does not replace the original startup-must-fail and no-target business
assertions. A preserved actual `ok=true` outcome after failed preparation is a
failed fixture case, regardless of its cleanup or callback delivery.

The non-returning preparation case is deliberately uninterruptible until test
teardown. At the original logical deadline the caller must reject while the
actual original native operation still owns `starting` and its waiters. The
failure must stay failed and cannot admit the next case. Whether a subsequent
source/package/nonce/PID-fenced force-stop safely cleans this exact disposable
test process is a separate proof that this host does not establish. Releasing
its latch afterward is labeled post-deadline teardown and cannot qualify as
timely cleanup or an accepted repair.

A cleanup-proof-pending conclusion exits with code 2. Successful host checks
can demonstrate failed-flow containment; they do not turn the prototype green.
The original 77 Android
business checks, the real terminal IPC, and the full Activity fixture have not
executed here. No workflow/profile/release entry includes this directory.

`activity.py` is a separate candidate integration probe. It extracts the complete
actual `ReservedCaseGate`, `reject`, native worker/registration hooks, and scoped
terminal callback methods. Its real Java UI queue executes admission on its own
identified UI thread. Eighteen controls cover normal completion, real retry join,
finite preparation failure with preserved successful startup side effects, queued
mode2 ABA, mode0 during preparation and after the original body enters, changed
contacts and stale callbacks. Private source IO, Gecko fetch and terminal finish
remain explicit host adapters. The complete terminal observer has separate host
controls; none of these run the original77 Android checks or a real fresh IPC.
Its success means `host-controls-passed-android-candidate`; Android and process
cleanup evidence remain required before qualifying the candidate source.
