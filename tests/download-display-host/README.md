# Bounded download display refresh

The JVM runners compile actual production members and the complete new snapshot /
row-binding helpers against explicit deterministic widget/database adapters.
The old download-names runner still executes its original 44 assertions and all
four historical preservation comparisons. A separately pinned, four-hunk inverse
removes only the reviewed38 DesignDownloads delta before those comparisons;
unknown edits and modified/duplicated approved hunks still fail.

`run.py` accepts `--before-ref 3e3be57bd26e0cfaaee636749a3e4b76c8ab56fc`
for the paired audit. The same 100/1000 saved rows plus one active task exercise
initial, unchanged and single-progress refreshes. Rendering checksums remain the
same; unchanged historical rows stop invoking bind/time-format/description setters.
The current variant additionally injects row/name/update-status/package read
failures through the exact production refresh member, preserving previous cards,
actions, filter and scroll until a successful retry. Renames, progress, stale
threshold/heartbeat, locale/timezone changes and current action payloads remain
observable.

`snapshot.py` runs the complete production single-statement reader and prior31
read/prune members pinned in `legacy31-read-members.json` against counted adapters.
The pinned member data avoids requiring a new historical Git fetch in shallow CI.
`sql.py` separately executes the exact SELECT and schema4 DDL in real host SQLite,
including a live WAL writer while the read cursor remains open.

The compound SELECT has explicit kind/time/rowid order. Its tie order preserves
what the current schema4 descending time index returns for the old ascending
prune scan, including equal DB times with different JSON times. The former query
did not declare a SQL language guarantee for ties; the paired real-SQLite check
therefore establishes equality for the current schema/index, rather than claiming
that every possible alternative query plan historically ordered ties identically.
Only display data is read. Authoritative saved-file persistence, deletion,
leases, ownership and the database schema are unchanged.

These checks count calls, parsed records and compare output. They do not measure
Android SQLite locks/I/O, actual layout, frames, phone speed, or ChatGPT scrolling.
Full history still loads and retains all its cards. The new compound SELECT may
perform ordering work in SQLite; its phone cost remains to be measured. This is
not paging, virtualization, background persistence, or a download-save rewrite.
