The runner compiles and executes the complete selected production
`WindowNetworkState` constructor and identity helper, its actual `mainline`,
the real `NetworkWorkspaceUi.runningConfiguration` consumer, and the complete
portable display policies. Native route identities and subscription labels use
the selected production methods. Context/preferences, URI parsing and the
region lookup are explicitly limited host adapters.

All 93 checks must pass. They cover foreign and missing identities; malformed
identity types, fractional and overflowing generations; malformed catalogue
rows; nested running configurations; reused slots; saved configuration
precedence; unchanged inputs; and preservation of owned fresh and old readings.
IDs are exact nonempty strings, matching the production display boundary. The
test does not introduce a new canonical UUID requirement.

A second JVM runs the complete actual Android fixture's 14 new controlled
identity projection cases and bounded logging/check method. All 14 must pass,
and the resulting raw projections must pass the same public validator as the
Android runner. This is a host replay of fixture methods, not Android execution.
The existing 88 chrome checks, 44 capture checks, 14 freshness cases and original
network checks remain separate regressions.

Run once per pinned desktop and Android JSON library:

```sh
python3 tests/window-network-identity-host/run.py \
  --java-home /path/to/jdk17 --json-jar /path/to/json.jar \
  --output /new/path/identity-results.json
```

`--before-ref <full commit>` executes that exact production constructor against
the same oracle. It does not fetch history, change expected results or relabel
the before-source as current. A normal current-source run needs no ancestor Git
objects. Reports record selected source hashes and retain complete selected and
generated Java, compile/JVM stdout/stderr, classes and an artifact manifest.
Existing results are never overwritten.

No Android scheduling, Binder, Gecko, native core, real network measurement,
physical phone or user account is exercised by this runner.

Current-source runs also compile a separate cold-core producer JVM: 36 additional
checks execute the selected production `running`/`live` methods, exact
`NetworkCoreApplication.observed/current` predicates, and exact route-receipt
matching. Proof construction, cached transport state, fingerprints and latency
are controlled adapters; no actual service IPC/capture is claimed. Current proof
ownership, recreated environments, stale core generations/PIDs/configurations,
degraded admission, and deterministic replacement between producer reads are
covered. Historical application JSON cannot create observed admission.

The original 35 cases retain their names and order. The configuration cutover
case changes both settings and cached core configuration. A separate settings-only
case keeps the old-core receipt observable but requires an empty running
projection and blocked connection admission; cached proof is not new-config proof.

These results live under `coldCoreProducerHostReplay`; the original top-level
93 checks and the separate 14 fixture projections retain their exact counts and
assertions. Old attempts and generated/raw evidence are never overwritten.
