# PocketChat Android AI 诊断

构建与设备验收见 [验收说明](ACCEPTANCE.md)，服务端协议见 [Responses 说明](RESPONSES.md)。

## Android 流程

1. 构建 `:app:assembleDiagnostics`，使用包名 `local.pocketchat.aidiagnostics` 和测试签名。需要项目固定的 Gradle 9.8.0、Android 37.1 平台及对应 Gecko caret AAR 和资产。升级入口在测试包中禁用。
2. 进入测试环境，长按底部「网页工具」。短按仍打开原有网页工具。选择最多三个原生标签页证据，配置 GPT 或 DeepSeek 的自控 HTTPS 网关和本窗口令牌。网关路径为 `/v1/diagnose`。
3. 即使环境断网，仍可预览本地证据。线路可用时核对预览里的网关、供应商、证据编号和完整诊断 JSON，再点预览中的发送确认按钮。标签页、环境、线路或设置在确认前改变时，重新选择和预览。重载或会话恢复后旧快照失效。后台标签页保持自己的匿名编号。
4. 助手展示网关回复和本地标签页编号映射。关窗、取消或超时后如果证据已开始写入，显示「网关可能已收到请求」。在同一窗口对同一网关、供应商和证据重新确认会复用请求编号。请求变更或重启服务后的处理见 [网关说明](README.md)。

安卓诊断包使用平台 HTTPS 证书校验。实际 Android 试验应使用自有测试环境里可经指定线路访问、证书可验证的合成 HTTPS 网关。下方本机 HTTP mock 供宿主验证。

## 证据和路由

- Gecko 原生回调采集加载开始、位置变化、加载错误、加载结束、内容进程崩溃和系统终止。规则识别 DNS、超时、证书或 TLS 等已公开信号。每个标签页最多 16 条事件。证据采用枚举、原生结构化错误码、相对毫秒和会话内匿名编号。具体导航归属为 `UNKNOWN`，因为 SDK 回调没有足够的请求标识。
- 只发送这次勾选并确认的证据。载荷没有访问过的网址、域名、页面内容、聊天、Cookie、浏览器认证头、密码、密钥或真实环境标识。网关访问令牌放在发给确认网关的认证头，保留在当前窗口。网页没有指令通道，模型没有工具入口。
- 内置线路核验当前环境的代理凭据并使用数值回环地址。外部数值 HTTP 代理和完整覆盖 VPN 绑定核验时捕获的 Android Network。线路或环境变化终止本次发送，已发出的字节无法撤回。普通直连、域名代理、HTTPS 代理、SOCKS 不可用。原下载的仅 Wi-Fi 策略保持原样。
- 本地 mock 使用两种 Responses 契约的合成响应。网关到模型的真实 HTTPS 出口和实收计费行为尚未验证。

## 验收范围

诊断候选采集 Gecko 原生回调并发送用户确认的脱敏证据。宿主回归使用合成数据与 JVM 边界替身，设备验收步骤见 [验收说明](ACCEPTANCE.md)。
