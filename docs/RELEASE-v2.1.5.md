# 2.1.5 · 浏览器稳定性与维护更新

版本 `2.1.5`，版本代码 `107`，从正式 `v2.1.4-gecko / 106` 继续维护。本次整合已确认的浏览器界面调整与后续稳定性修复。正式安装包、原签名和绑定源码的验收结果以 GitHub Release 为准。

## 浏览器与环境入口

原“会话”页按浏览器组织，环境卡片作为进入相应浏览器环境的入口。Gecko 常显地址入口，保留后退、前进、刷新／停止与主页操作；顶部环境胶囊仍可点按输入网址、长按切换环境。主页默认仍为 ChatGPT，已有主页偏好继续保留。

地址输入、打开主页、前进和后退，不再因旧回复记录、文件选择或独立下载处于忙碌状态而被拒绝。页面快照采用有限等待时间；离线输入的目的地会保留，网络准备完成后继续处理最新选择。旧页面、旧网络回调和旧通知恢复不能覆盖后来输入的网址。

离开网页会使旧页面在应用侧的观察结果失效，并保留必要的发送与任务记录。网页自身的回复连接或上传可能随离开页面中断；独立下载和原生任务继续按各自生命周期处理。公共网址、环境身份、网络与内核保护仍决定请求何时能够实际发出。

五页继续采用原生 Java View。字体、导航、阅读入口和浅色玻璃沿用现有实现；原有环境管理、搜索、排序、下载保存位置、网络配置及设置入口均保留。HTML 文件继续作为设计预览。

## 文件、权限与页面归属

- 文件选择请求携带独立请求编号和页面代次。旧窗口迟到的返回结果不会交给新请求；关闭旧请求时，回调内新开的选择器可以保留。
- 页面切换、Activity 退出或宿主接管时，文件与权限请求按原持有者清理。回调异常不会阻止剩余生命周期收尾。
- 回复完成、观察到网页停止及解除等待的保存逻辑集中处理；保存确认后再释放等待记录，重启时不把数据库已确认的完成／停止任务重新恢复为等待。
- 下载取消、临时副本和保存目标按实际文件归属与使用状态处理，避免清理仍被读取的副本，或把缺失副本误报为可用。
- 保存副本只有在复制及流关闭成功后报告成功；提供方清理结果无法确认时保留明确反馈。

## Gecko 启动与生命周期

修复已安装内建扩展的冷启动等待链：内核可能等待首个窗口来启动扩展后台，而应用正在等待扩展桥接才能打开网页。启动时使用临时的空白内核窗口完成这一步初始化；它不挂接界面、不加载网页，并拒绝页面导航。正常网页仍经过原有身份、线路和隐私保护检查。临时窗口在正常启动、失败、禁用或销毁时清理。

界面回调集中绑定到当前 Activity，释放时只解除本实例持有的回调。新的宿主接管后，旧 Activity 的迟到退出不能解除新宿主的绑定。低内存恢复、弹出页关闭和页面提交继续核对既有导航代次。

Gecko 通过 GeckoView 接入；Chromium 通过 Android 系统 WebView 接入。系统 WebView 是 Chromium 的接入方式。两种内核各自保留环境配置和数据边界。

## 维护与验证

把文件选择、页面生命周期、后台指纹事务、回复终局保存及文件清理的责任边界整理清楚，并补充实际编译当前生产代码的行为检查。

历史发布证明固定读取真实 `2.1.4` Git 对象，保留原有差异、断言和负控；当前行为检查继续使用当前源码。维护无关方法时不再要求不断新增整文件反向适配层。

设备验收共用既有原生事件记录读取逻辑，保留来源、安装包、调用身份、事件顺序、摘要和超时检查。横屏验收通过实际屏幕旋转配置，继续要求准确的视口尺寸、完整触摸区域与安全区。

正式发布沿用完整 APK 构建、原有回归、两核及同环境 CPU／IP 时区／TLS 验收流程，并使用原应用签名。受控模拟器和 JVM 边界检查各自记录范围；本发布说明不把它们称为真实账户、物理手机、高刷新率流畅度或公网连通性证明。

## 支持范围

国家或地区图标仍只依据节点名称或标签显示。图标、预览配置和测试数据不代表真实 IP 归属或连接成功。

两核指纹能力、Worker、独立时区、CPU 和 TLS 的支持边界沿用 [2.1.4 发布说明](RELEASE-v2.1.4.md)。本次没有扩大这些能力的覆盖承诺。
