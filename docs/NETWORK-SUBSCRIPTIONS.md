# 入口与出口订阅

网络页保留三个入口：窗口网络、入口、出口。入口和出口各自维护订阅名称、地址、节点列表、最近成功更新时间及更新失败原因，支持添加、编辑、更新和删除。出口页也保留用户已有的手动 SOCKS5 出口。

每个环境明确保存自己的组合：入口节点 → 固定出口 → ChatGPT。新环境默认自动优选入口；用户可以限制参加优选的入口池。旧环境继续使用原来的手动、随机或优选设置。固定出口由用户明确选择，既不随机，也不设置全局默认值。

订阅更新只更新共享节点库。正在运行的环境保留两份独立的加密订阅快照；在环境编辑器中保存后，沿用现有安全空闲时机应用新组合。聊天、上传或下载期间可以编辑、保存候选配置，不中断当前操作。

节点身份由 Mihomo 实际解析的连接配置生成，而不是节点名称。刷新后保留仍然有效的选择和入口池，节点改名也可以识别；同名节点更换服务器、认证或传输配置后，需要重新选择。多个相同配置的别名优先保留用户选定的名称，不能任意挑选别名。

修改订阅地址、删除订阅、节点消失或出口协议不支持时，编辑器清楚说明需要重新选择的项目。已有环境的快照不会被共享库删除。新环境复制网络时复制有效的入口和出口快照，不复制登录、聊天草稿或尚未应用的候选配置。

底层复用项目现有 Mihomo 内核、节点解析、链式 SOCKS5、完整线路测速、出口核验、连接预热和环境隔离。订阅中的固定出口目前支持 SOCKS5；其他协议在选择器中说明原因并禁选。生产路由按保存的节点指纹和原节点名匹配唯一出口，异常时停止连接。入口优选和探测均使用同一个固定出口。

验证分三层：实际文件锁与候选事务的主机检查；Android 上的真实订阅解析、Keystore 快照及 Modal 操作；真实双认证 SOCKS 链路与官方 Gecko HTTPS/H2 请求。受控线路结果只验证客户端的行为，真实节点的速度和延迟仍需在相同设备、目标网址和链路条件下比较。
