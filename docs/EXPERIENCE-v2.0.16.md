# 2.0.16：分享修复与体验测量

## 先修复整条线路分享

2.0.15 的分享器对完整订阅执行通用 YAML 对象构造。原生 Mihomo
能读取的配置，可能因无关分组中的别名、嵌套或标签而在分享前失败，
显示“读取分享配置失败”。13 个固定合成样例复现了这类差异；这不是
对用户私有订阅内容的确认。

分享器现在先读取首个 YAML 文档的受限语法树，只构造选中的节点。
仍限制输入字节、语法节点、别名、递归深度和选中节点的展开量；
拒绝重复字段、循环引用及不支持的选中节点类型。原生节点指纹复核、
接收端预览及出口重新校验继续执行。其他节点、订阅地址和网页数据不导出。

宿主验证：Android JSON 与桌面 JSON 各通过 87 项检查；修复后同一组
13 个样例与实际 Mihomo 解析结果一致，其中 2 个重复键样例继续拒绝。
Android 回归覆盖手工/订阅出口的整条线路、单独入口/出口、接收端预览应用，
并检查分享不改变活动线路快照和草稿。宿主结果不能替代 Android 回归结果。

## 固定体验实验

先冻结包含分享修复和测量工具的源码，完成构建，再测未优化基线。
只根据这次基线选择一个实际瓶颈。每轮只修改一处产品行为，使用同一
工作负载交替运行基线与候选；没有可确认改善就撤销产品修改。

专用 API 35 模拟器运行实际 MainActivity、AppHub 与 GeckoView，保留正常
观察器和计时器，动画倍率固定为 1。唯一网页适配用于把受控 localhost
长对话映射到原有网页路径，不使用真实账号。固定流程为：冷启动进入长对话，
往返网络/下载/设置，收起及展开顶部栏，切换暗色和亮色，后台返回。

每次构建绑定完整源码 SHA、原构建 run/attempt、安装包字节及 SDK 身份。
前后两版的测量代码和模拟器准备代码必须相同。在同一模拟器执行 A-B-B-A，
每阶段预先声明 3 次完整流程，保存全部原始样本；失败样本不会被补跑替换。
每阶段在计时外重新安装合成测试包，正式包和用户数据不参与实验。

记录启动可用时间、真实 Android 输入至原生 View 绘制的响应时间、前台
Choreographer 间隔和 HWUI 帧、应用进程族 CPU 与 PSS。若进程权限或生命周期
使测量不完整，明确记录缺失或下界，不用零补齐。View 绘制和 HWUI 不能单独
证明 Gecko 合成器的最终屏幕呈现。每一步检查网页文档、会话、Cookie、草稿、
静态回复内容和发送次数。主题切换记录受控网页的实际媒体查询与背景色，
验证 Gecko 颜色偏好；ChatGPT 专用主题通信仍由原主题回归独立验证。

结果报告固定包含：原始数据、唯一产品修改、新数据、仍未解决的瓶颈。
受控模拟器结果不代表真实 ChatGPT、流式回复、上传、用户线路、实体手机
或百度输入法表现。
原发布回归及输入检查独立执行，体验实验不替代发布验收。
