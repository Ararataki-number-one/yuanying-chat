# 从 2.0.20 开始的体验修复与测量

基线为正式版 2.0.20（73），源码 `da5004111eaf3e20322ca1fca3f756db82f44c90`。本轮按正确性修复、减少可测重复工作、实际设备验收分开记录。网页持续亮色是用户确认的症状；现有证据尚未确定其唯一触发原因。

## 网页配色

旧脚本在受控页面中返回设置成功时，聊天区域仍可保持白色，存储写入异常也可能返回成功。新流程用隔离世界的文档标识、当前端口和递增指令版本建立回执，收到或改完属性都不等于颜色确认。原生端只接受当前绑定、类型及范围正确的结果；每次同步最多三次、每次等待 1500 ms，断开后取消旧任务。

采样重新读取当前主题偏好、根属性和有限数量的聊天区域 computed style。透明或被遮挡区域、无法解析的颜色、后台不可见页面均保持未确认，不根据期望主题编造颜色。颜色一致但偏好不可写与完整确认分开显示。恢复到前台、页面切换及主动重同步会建立新的检查；这些动作不重载网页或重建浏览器。

独立复核实际发现并关闭了过期存储结果、透明祖先、透明命中后代三类受控假成功，保留了深浅配色的正向对照。JSDOM 几何适配器不提供真实渲染证据。补充的 Android fixture 使用真正的 Gecko、原生消息及生产控制器，但页面仍是合成 CSS：仅 integration 变体额外允许固定 loopback 路径，资源覆盖从本次生产源码精确生成并记录哈希；release 的来源域和资源保持生产版本。它不代表真实 ChatGPT 官网通过。

## 故障恢复

初版修补虽然通过 32 个搜索阶段 host 场景，但测量替身在错误的时点建立 binding，掩盖了并行 C 的另一个问题。重新使用完整生产 producer、低层 probe、ticket 和策略后，旧源码能确定性复现 C 的底层正向结果被 serial 推进改成失败，并最终停止自有 core。

最终恢复 scope 仅允许自己授权的 serial 推进。真实 producer 的 18 个场景及独立复核覆盖普通／服务路径、选择尚未确认窗口、配置／core／token／controller／维护代次／期限变化及 scope 结束。原 32／28／18／52 项检查与 LatencyPolicy 89 项保留。健康换优及 FixedExit 继续采用严格绑定。低层 API、控制器、进程和出口核验在 host 中各有明确替身边界，这些结果不等于 Android、真实 HTTPS 出口或用户线路验收。

## 下载保存

同一组生产方法故障注入在基线上得到 14／39，捕获 8 次界面队列异常逃逸；修补后 39／39，原恢复 42、续传 37 项保留。持久化失败先撤销传输所有权、停止数据流，保留实际存在的部分文件；失败处理不会无限递归保存。只有必要记录提交可靠后，取消才可继续清理。

未知外部提供者保留 pending 信息，不能把没有核验能力等同于保存完成。独立检查还发现“查看待确认文件”缺查看器时会误称已保存，现已区分已确认与待确认入口；28 个真实生产回调／重载 host 对照覆盖 MIME、启动成功、缺查看器和权限拒绝。查看成功也不会把 pending 晋升为已保存。

持续存储故障时，当前进程可保留暂停元数据和仍存在的文件；无法确认持久写入，就不能保证重启后恢复。测试中的磁盘与 Android API 适配器不代替真实文件提供者的故障注入。

## 冷拨号候选

最小补丁只修改冷 `pocketPrepare` 的瞬时传输错误分支，保留内部至多两次尝试、冻结路由、原 ctx 期限和外层停止标记。冷 CONNECT 命令及认证／协议错误不在本次扩展范围。

独立候选源码 `51de04745164e25ab88048d4afff5ea709111936` 的 CI `40290272336/1` 实际执行：旧 70 项通过，新增 2 项保护通过、指定 3 项失败；修后 75 项全部通过，并用原构建工具生成 ARM64／x86_64 和真实 receipt。分片、完整哈希、ELF 与输入回执逐一核对后才集成。最终发布源码仍需原独立重建及整套 Android 发布验证，候选成功不替代这一要求。

| 下载 URI／时间查询 | 三个非唯一索引；36 项真实主机 SQLite 检查覆盖迁移、重复 URI、查询计划、结果及回滚 | Android 数据量、主线程调用和帧耗时 |

Cookie 的 45 个扩展控制与原始 10 项回归分开运行；恢复失败不覆盖完整日志，native bulk clear 的等待必须覆盖新读取和提交。实际读写故障、退出登录顺序及尾部微任务窗口均单独注入，计数不是手机速度。

后续仍按单变量流程：先在同手机、同对话和历史量下记录网页长任务、帧耗时、SQL 和主线程磁盘调用；逐项减少滚动分析、历史全量读取／绑定，再复跑相同流程。没有设备数据时，不给这些改动写提速结论。

上传已交付副本的安全退役、订阅出口重复解析、空闲权威文件工作、大入口池发现节奏、备用出口核验、分享脱敏错误细分和无入口旧组件清理，仍列为后续项目。保留文件引用／所有权、环境隔离、退出登录与事务恢复要求，不用统一清理或删除锁来替代。当前修复不宣称这些项目已经完成。
