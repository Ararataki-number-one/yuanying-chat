# 网络性能方案（1.5.14）

目标：缩短网页连接和请求等待，减少使用中的网络干扰。保留环境隔离、候选配置、固定出口核验和断网保护。优化只适用于应用内置代理；手机网络 / VPN 不由应用擅自修改。

## 用户看到的变化

“网络 → 编辑网络 → 入口选择”增加 **低延迟优先**，与自动随机、手动指定并列。用户勾选可参与优选的入口，保存并应用后生效。弹窗关闭、切换模式、勾选节点都只修改候选。旧环境不会自动改成新模式。

网络卡片保持原有密度。测速结果和窗口详情另列 **ChatGPT 网站首响应**、复测耗时、检测时间；不把线路延迟与网站响应混成一个数字。网站要求验证、拒绝检测或者不支持 HEAD 时明确说明，不把它们误报为线路断开。

## 入口选择

- 比较手机 → 用户允许的入口 → 已选固定出口 → 目标网站的完整链路。
- 沿用最近 30 分钟、最多 20 次的延迟、成功率和波动评分。网站有足够近期成功样本时优先参考网站数据，否则参考原线路数据。
- 启动优先恢复已核验的上次入口；没有可用记录时优先试历史优质入口，再寻找可用入口。无需等待全部节点测完才显示网页。
- 低延迟模式只在空闲时优化。至少 3 次样本、连续两轮胜出、评分改善至少 25% 且 100 ms、切换间隔至少 5 分钟，才替换健康入口。
- 随机模式保留勾选池和重新随机；不因另一个入口稍快而替换健康随机结果。手动模式不转到其他入口。连续两次完整线路失败后，空闲时仅在允许池中尝试恢复。固定出口异常仍停止连接。

## 网站检测

对 `https://chatgpt.com/` 发少量 HEAD 请求，不带登录 Cookie、账号令牌或聊天内容，不跟随跳转，不下载网页正文。首次响应耗时包含代理建连、TLS 与响应头等待；第二次检测观察复用连接后的耗时。不是纯 TCP RTT，也不是模型生成耗时。

候选网站检测使用专门的本机回环代理监听器，指向候选入口与同一个固定出口。它不修改实际网页的入口选择器，页面无需重载。

自动探测每轮最多 4 个入口（当前、近期优质备选、轮换探索节点），线路探测最多 2 个并发，网站逐个检测。回复、提交、导航、上传、下载或网页忙碌时取消后台探测并延后切换。健康内核的存活检查保留；出口核验与发送前核验保留。

## DNS 与连接

通过固定出口比较四个固定 HTTPS DNS 服务对 `chatgpt.com` 的真实 A 查询，不把用户的任意域名发送给额外服务。每个空闲维护周期最多测一个 DNS 服务，最多 4 秒，有效结果缓存 24 小时。只接受匹配查询、成功且包含答案的 DNS 响应。

按出口和订阅隔离 DNS 结果。完整比较后选择有效响应更快的服务；只在下次正常连接时使用，避免配置重载中断长连接。节点服务器的启动 DNS 保持原有路径；网站 DNS 始终走固定出口，不增加直连回退。使用内核 DNS 缓存和 TCP 并行连接能力。

网站 HEAD 和成功的出口核验读完并关闭响应流后允许连接池复用；失败或取消立即断开。浏览器继续使用自身的连接池、独立目录和登录存储，不为优化创建额外浏览器实例。

## 验收

1. 模式保存 / 恢复、跨订阅池约束、空候选、池变化和取消编辑。
2. 低延迟选择的稳定性阈值、旧模式保持、忙碌延后、过期样本与退出取消。
3. 使用实际 Android 和 Mihomo 内核，通过两个受控 SOCKS 跳验证网页 / DNS 探测不改变当前入口，出口一致，失败不直连。
4. HTTP 验证限制、HEAD 不支持、超时和旧连接结果不冒充可用线路。
5. 原有浏览器、附件、下载、缩放、登录持久化、双环境网络与自动更新回归；编译 ARM64 正式包。

发布时只报告实测结果。受控线路用于验证行为，不据此承诺用户网络能降低多少毫秒；实际收益需使用用户订阅和固定出口对比。
