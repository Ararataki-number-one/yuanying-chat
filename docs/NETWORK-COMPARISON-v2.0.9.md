# 网络耗时对照：2.0.9

## 已知条件与边界

用户确认电脑与手机处于同一 Wi‑Fi，手机未开启其他 VPN。Clash 界面入口约 101 ms、出口约 141 ms 是分别显示的测量，不是已验证的整条链耗时，不能相加或与应用 400 ms 直接相减。用户使用 Clash 自带测速，具体 URL 尚未确认。

应用继续使用 Mihomo v1.19.31，当前检测地址为 `https://www.gstatic.com/generate_204`，方法为 HEAD、成功状态 204。每次探测经当前入口和固定出口；首次包含建链，第二次只有内核证实复用连接且响应成功才能称为热连接延迟。探测不借用业务预认证池。

## 本次发现与修改

旧版备用 SOCKS 认证连接总寿命只有 8 秒。阅读超过这个间隔后，尚未使用的连接已经主动关闭，下一条连接再次经过入口连接、SOCKS 方法协商与认证。新版寿命为 30 秒；建立备用连接的期限仍为 8 秒，且受剩余寿命约束。没有提高四条容量，没有定时保活或补充，没有预发目标 CONNECT、TLS 或聊天内容。

正常聊天已有的 HTTP/2、WebSocket 连接沿用原行为。30 秒后仍回收闲置备用连接。远端服务器更早关闭备用连接时，沿用原有仅在交给浏览器之前、同一冻结线路上的一次回退；不重发聊天数据。

## 分段诊断的实际含义

| 字段 | 测量边界 |
| --- | --- |
| chainMs | 首次 Proxy.DialContext 调用，包含入口连接及固定出口 CONNECT；远端 DNS 可能在其中 |
| tlsMs | 首次网站请求的真实 TLS 回调；HTTP 为 0，未观测为 -1 |
| responseWaitMs | 首次请求 WroteRequest 到 GotFirstResponseByte；包括线路传输和服务端等待 |
| dnsMs | -1：未单独观测。SOCKS 服务器内部 DNS 不能从客户端单独拆出 |
| firstMs / warmMs | 保留原始首次与第二次请求计时，不能用上述分项直接替换 |

分项来自本次请求的单调时钟和实际 transport 回调，不采样 Cookie、请求正文或凭据。它们只描述检测请求，不等于网页渲染时间或模型生成时间。HTTP 自动重试的次数继续单独记录；分项不承诺在重试场景下相加等于总时间。

## 受控验证设计

- 同一实现、同一 SOCKS fixture 和每阶段 60 ms 延迟，对照旧 8 秒与新 30 秒策略，均等待 9 秒再连接。验证目标 CONNECT 没有提前发出、没有重放数据，并记录真正拨号耗时。
- Android Gecko + HTTP/2 双 SOCKS 链：首组实际请求在认证后停顿 9 秒，再验证是否借到原来的认证 socket。其余失效、出口拒绝、线路切换、旧连接恢复、WebSocket 连续性检查照常运行。
- 备用连接自然过期检查改为对应 30 秒的有界范围，同时确认服务器没有主动关闭、没有提前目标流量。
- 真实 HTTP/TLS 服务验证三项分段、证书验证和首响应延迟；旧无分段记录保持兼容，缺失/错误类型/超界分段不能变为有效诊断。

## 本机受控结果

最终原生测试源码的本机运行：阅读停顿 9 秒后，旧策略 **245.95 ms**，新策略 **61.59 ms**，减少 **184.35 ms**。这是每个模拟握手阶段设置 60 ms 的实际 socket 对照，每种策略一次测量；不是公网均值，也不是手机的 400 ms 已降到 200 ms。首次独立试跑同一场景为 245.27 → 63.68 ms。

HTTP fixture 的首次结果为 52 ms（建链 1 ms、无 TLS、响应等待 50 ms）；TLS fixture 为 92 ms（建链 1 ms、TLS 40 ms、响应等待 50 ms）。分项采用毫秒取整，不能据此要求总和严格相等。

本机 70 项原生主测试、89 项测速策略检查、297 项配置／迁移／发布契约检查通过。Android 与正式发布结果在同版发布验证记录中另列。

## 用户公网对照步骤

1. 保持同一 Wi‑Fi、同一入口的完整配置和同一固定出口；在两端确认出口 IP 一致。关闭其他测试与大流量传输。
2. 在 Clash 核对实际检测 URL、请求方法、成功状态及是否使用统一延迟；必须测“入口 → 固定出口”组合，不能用入口节点单测代替。
3. 两端使用同一 URL（本应用如上），交替测量至少五组，分别记录首次与真正复用结果、失败次数和时间。比较中位数与波动，不能只选最低一次。
4. 手机在网络详情查看分段，通过“连接详情 → 复制耗时诊断”获取不含凭据的结果。对照发现主要等待在建链、TLS 或网站后，再针对该段改进。
5. 单独比较 ChatGPT 页面可用和附件上传时间。网站服务端状态、不同设备 CPU、无线链路和 CDN 分配都可能影响结果，不以延迟数字替代使用体验。

本次云环境没有用户节点配置或同一 Wi‑Fi 的设备，不能声称完成了用户线路的公网 A/B，也不能保证达到 200 ms。
