# 1.5.18 · 网页连接与提问恢复

用户报告真实网页提示 `Browser app server websocket closed`，以及加载动画期间应用提示“对话已改变”。第二处已有明确的应用代码原因：轮询把暂时缺少 DOM 中的绑定消息当作永久失去绑定。第一处还不能根据截图判断服务器端原因，但确认应用在出口核验网站暂时失败时会关闭整个代理核心，可能打断仍然健康的连接。

| 文件 | 修改与作用 |
| --- | --- |
| `page-driver.js` | 以明确证据区分“原提问暂时没有渲染”和“对话确实变化”。首页分配对话地址时核对稳定消息 ID 与正文；仅识别当前有效网页错误，避免历史文本影响新任务。 |
| `ChatSession.java` | 页面加载中保留 pending 和发送记录。加载、错误和导航都重置完成采样，恢复后重新确认完整回复。主动恢复网页前在后台存草稿，再核对地址、任务与最新草稿，避免异步写入期间的新输入丢失。 |
| `WebReplyObserver.java` | 加载或待绑定观察不能计入回复完成窗口，显式重置样本。 |
| `ReplyState.java` / `MainActivity.java` | 当前网页报告连接中断时，现有菜单提供“恢复网页连接”。中央说明框解释恢复只重开网页，不重新发送或自动重试工具任务。错误消失或开始导航后移除过时入口。 |
| `NativeNetwork.java` | 区分核验服务暂不可用与出口不一致。只有已有核验凭据且连接身份完全相同的路线可以保留；仍然拒绝未知新路线、新发送的失败核验与真实不一致出口。后台核验有退避。 |
| `app/build.gradle` | 正式版本更新为 1.5.18 / code 44。 |

新增和扩展主机与实际 Gecko / Mihomo 回归，检查加载恢复、地址分配、错误作用域、稳定完成判断、草稿与无重复提交，以及核验故障期间真实长连接仍能通信。发布流程检查当前源码对应证据，使用原证书签名并更新公网下载和自动更新源。

不修改官方网页消息 UI，不替代网站的工具服务器，不承诺客户端能消除网站服务器内部的全部连接错误。
