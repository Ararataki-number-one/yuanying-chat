# 2.0.47 候选2 · 十轮流畅性优化

本次基于 `5900426428e00a95acf5126f6154f34ff2d46930`，在已完成的体验改动上，把重点转为减少主线程负担、重复刷新和后台堆积。以下十项均已修改实际生产代码，没有增加新的性能设置入口。

| 轮次 | 已实施改动 | 固定工作量验证 |
| --- | --- | --- |
| P1 | 下载列表复用监听器，只写入改变的选择和显示状态 | 40 行 × 100 次刷新，重复控件写入／监听器安装由 24,400 次降至 0。 |
| P2 | 下载搜索结果和页位置建立可复用索引，避免翻页重复归一化、排序与扫描 | 10,000 条记录的后续 6 页，文件名读取由 1,506,444 次降至 0；已完成页的元数据映射不再重复复制。 |
| P3 | 下载后台读取合并相同版本请求，过期查询在读取前取消 | 100 个排队查询只处理最后一个；过期回调全部完成，保留其他窗口的请求。 |
| P4 | 环境目录、进程与默认环境快照移到后台，队列最多一个正在执行和一个合并后的刷新 | 100 次集中请求只执行 2 次读取；离开页面不再排队，旧生命周期结果被拒绝。 |
| P5 | 环境卡片和筛选控件持续复用，心跳与隐藏字段不触发行重绑 | 100 次心跳变化产生 0 次行重绑；一个环境改名只更新该行。保留滚动与焦点。 |
| P6 | 环境搜索复用快照索引，连续输入合并后渲染 | 100 次连续输入新增目录读取为 0，只进行 1 次合并渲染。 |
| P7 | 本机历史检索复用元数据快照、解码缓存及扫描进度 | 重复查询新增 SQL／JSON 解析为 0；增加 30 个结果仅检查 30 个新候选。 |
| P8 | 会话内搜索结果供多页复用，长文本预览只检查可见前缀 | 20 次相同查询分页新增归一化／消息扫描为 0；百万 UTF-16 单元样本生成 120 码点预览只检查 121 码点。 |
| P9 | 会话状态立即同步，原生控件的集中通知按帧合并 | 1,000 次集中通知仅排入 1 个刷新并展示最终状态；逐次同步模型引用，文件下载使用的会话地址不延迟。 |
| P10 | 聊天下载卡片仅在内容变化时重绘；统一键盘／专注模式的可见性控制 | 100 次不变通知的文本赋值由 400 次降至 0；进度、不确定进度、颜色重复赋值均降至 0。100 次相同布局通知不再反复切换导航可见性。 |

这些数字是执行生产源码得到的操作计数，不是手机 FPS、耗时或卡顿率。P1–P3 的“之前”对应本次性能优化前已加入下载检索／收集功能的检查点，原始样本及 SHA-256 固定在 `tests/download-performance-host/baseline/`；P10 的前后对照直接使用候选2原始提交与本次源码。不同基线没有混称为同一发布版本。

缓存有失效规则和边界：下载按数据版本、查询与视图生命周期失效；历史打开新工作台或点击原有刷新按钮时重建快照。历史解码 LRU 上限为 96 个文档／2,097,152 个 UTF-16 字符，每个文档的归一化缓存另设上限。可见结果与阅读窗口持有的副本不计入该 LRU，不承诺整个进程只有这一内存用量。

  --android-jar /path/to/android-37.1/android.jar
