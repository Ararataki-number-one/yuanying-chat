# 主流指纹浏览器工作流对照与底层打磨

本轮按用户要求，以 AdsPower 的环境工作流作为主要参照，Roxy 的 Windows / macOS 使用体验作为补充目标。优先处理独立环境的运行质量；插件和网络新功能继续暂停。

## 可核实依据

- [AdsPower 官方组织](https://github.com/AdsPower)：公开说明按 profile 管理不同账号和浏览器指纹。
- [AdsPower 官方 Local API](https://github.com/AdsPower/localAPI/blob/main/README.md)：分别提供打开、关闭、查询打开状态、环境配置增改查、分组和删除环境缓存。原文将配置管理与浏览器操作分开。
- 本项目已有的用户界面参考：[yuanying_ui_reference.html](ui/yuanying_ui_reference.html)。后续外层页面校准继续使用这份参考。
- Roxy 体验由用户提供。本次 AdsPower 帮助中心、Roxy 官网和比特浏览器官网请求均返回网络代理 403，没有取得最新产品界面，也没有运行它们的桌面程序。因此以下是公开工作流对照和项目改造目标，不能作为这些产品内部实现、实际性能或登录成功率的结论。

## 对照与落实

| 使用环节 | 对照目标 | 项目当前问题与本轮处理 |
| --- | --- | --- |
| 环境打开与运行 | 以环境为单位管理浏览器生命周期，配置与打开状态各自明确 | 原运行进程和独立 profile 保留；补上网页被系统关闭后的 session 重新打开流程，恢复继续使用同一 runtime 和 profile |
| 登录与网页跳转 | 一个环境内完成身份页跳转，新窗口关闭后回到原窗口 | 按窗口保存返回历史；父页面不再因为关闭子窗口而丢失可返回状态；关闭后台子窗口不会关闭当前窗口 |
| 环境独立性 | 环境设置、账号存储和运行操作有明确归属 | 网页执行与 Cookie 请求绑定到确切桥接连接，旧文档或旧连接的结果、断开与超时只能结束自己的请求；沿用当前环境网络守卫 |
| 连续使用 | 导航、检查状态和重复读取登录信息不会持续积累资源 | 已完成、取消与超时请求立即移除超时任务；关闭浏览器时同时释放子窗口和待完成请求 |
| 页面可用时机 | 页面已有内容即可进入阅读与交互 | 用官方内核首次内容绘制回调报告页面可见，保留加载完成回调作为后备；不再只等全部资源结束后报告可见 |
| 快速导航 | 用户主动停止旧加载不应显示网络故障 | 停止加载时作废原加载目标，忽略旧加载晚到的停止结果；仍允许当前已绘制页面继续交互 |
| 异常恢复 | 故障有真实恢复路径，账号数据不会因为恢复被清空 | 重新加载会打开已关闭的 session；网络守卫阻止时不重建或联网；后台父窗口已关闭时，返回后进入可重试状态 |

## 改造边界

网络配置、订阅解析、SOCKS5、固定出口和出口核验继续调用现有实现。环境的数据目录、登录存储与后台回复服务没有迁移。网页仍由真实 GeckoView / System WebView 加载，官方输入框、模型、消息和标题没有替换。

关闭的网页 session 在重新打开后需要重新加载，内核原文档的返回历史和未持久化的网页表单不保证恢复；本轮不将这些行为包装成完整会话恢复。Google / ChatGPT 的真实账号登录仍需要真机验证，本轮的受控 Cookie 验证不能代替真实登录。

## 本轮验证

1. JVM 执行生产请求管理器，验证旧连接干扰、重复结果、重入重试、超时、Cookie 桥接切换和连续 1000 次调用的资源释放。
2. Android 实际内核中，两个环境各自打开子窗口、子窗口返回、关闭后返回父窗口，并检查父窗口历史仍可返回。
3. 在实际 Android 内核中关闭 session，并注入官方 `onKill` 回调契约，验证网络阻止时不重建、恢复后仍使用原 Cookie 和网页存储；此测试不等同于实际制造系统内存不足。
4. 后台父窗口被关闭后，前台子窗口退出，再恢复父窗口。
5. 页面附带慢资源，检查实际首次绘制事件早于资源加载完成。
6. 在慢资源结束前主动停止加载，检查不会显示网络故障，已经可见的文档仍可使用。
7. 继续执行原双环境隔离、HTTP / SOCKS、远端 DNS、worker、WebSocket、重启、清理、封闭初始线路和正式外层界面回归。

执行结果将在编译和 Android 回归完成后写入本轮验证记录。后续以完整登录、长时间前后台切换、手机键盘与缩放体验继续验收，而不是以增加选项数量衡量完成度。
