# 公共计算与下载排序重构

基线：正式版 2.0.7 之后的 `7e0247939dd4029ba994c3d6fd8be1965d42f8fe`。
本轮集中清理重复哈希实现、订阅快照重复计算和下载排序开销。没有修改版本号或发布安装包。

## 修改范围

| 文件 | 修改与兼容边界 |
| --- | --- |
| `Sha256.java` | 统一 UTF-8、SHA-256 和小写十六进制编码。使用字符表代替每字节 `String.format`；每次调用独立创建摘要对象，避免跨线程共享可变状态。 |
| `NativeNetwork.java`、`NetworkSourceSelection.java`、`EnvironmentSpecMigration.java`、`NormalCaretSdkReceipt.java`、`AppUpdatePolicy.java` | 五处原有实现复用公共编码。已有入口保留；环境身份、凭据修订、缓存键、构建来源和 APK 校验仍使用相同的摘要算法与字节编码。流式下载校验、取消和损坏文件清理流程保留。 |
| `NetworkSourceSelection.java` | 入口与出口复用同一个快照写入方法，每份订阅的完整数据哈希从四次减少为一次。复用仅发生在本次事务内，无跨请求摘要缓存。记录名称、字段、插入顺序、文件锁、写入顺序、七记录回退和旧快照读取规则保留。单独生成元数据时也避免重复扫描数据。 |
| `DownloadListPolicy.java` | 每次刷新捕获排序字段；比较期间复用状态、时间和必要时计算的身份键。移除每次状态判断的临时数组。仍返回原始行对象；正在下载优先，时间降序，同时间按原身份排序，原去重规则保留。下次刷新重新读取状态和时间，不复用过期排序值。 |
| 测试与显式编译清单 | 新增共享摘要兼容检查，补充下载完成后的排序变化以及七个快照写入位置的故障恢复。JVM 编译入口与 CI 清单加入新依赖。 |

GeckoView、ChatGPT 网页、输入与附件处理、环境目录、Cookie、草稿、代理链、连接池、提醒和外观设置均未改动。本次不改数据库或配置 schema，也不迁移密钥与存储目录。

以上没有执行 Android 模拟器或 ARM 真机。本轮没有重新构建完整 APK、进行手机端滚动帧率验收或测量公网延迟。

## 局部性能对照

同一云端 JVM、相同输入，前后交替执行，取七批中位数。最后一轮单独运行，没有同时执行本次编译或回归。

| 工作负载 | 基线 | 重构后 |
| --- | ---: | ---: |
| 排序 1000 条文件 + 250 条任务，含空记录与重复项 | 3.194 ms | 0.861 ms |
| 保存 1 MiB 入口订阅快照，host 普通文件夹具 | 14.257 ms | 7.161 ms |
| 1 MiB 单次 SHA-256 | 1.333 ms | 1.331 ms |

大块数据单次哈希仍主要受摘要算法限制；收益来自取消重复计算。此表是局部微基准，受 JVM、文件系统及云端调度影响，不能解释为整机提速比例、Android 加密写盘速度或网络延迟改善。

复现命令（需要 JDK 17、现有 JSON-java 测试依赖和基线 git 对象）：

```sh
python3 tools/gecko/run_refactor_hot_paths.py \
  --json-jar /path/to/json.jar \
  --output /tmp/refactor-hot-paths.json
```

原始结果与当前源码摘要见 `verification/refactor-20261017/`。测试发生在工作区变更上，因此报告如实保留 `sourceDirty: true`，以各源文件 SHA-256 标识被测代码。

## 后续清理边界

`NativeNetwork`、`GeckoWebView`、`ChatSession` 中仍有较多状态和生命周期耦合。本次没有为了缩短文件而整体拆分它们；后续应分别建立启动／恢复、文件选择、页面回调的行为基线后再拆分职责，避免将现有登录、上传和后台恢复问题重新引入。

后续发布准备：上述记录保留第一批重构时的真实状态。2.0.8 在此基础上将环境节点池去重改为集合，继续保留原排序和身份；另行执行源码对应的完整构建及 Android 发布回归。
# 2.0.8 发布回归补充

首次发布回归（源码 `93de4a14c9c8030394d38fdd7ed7884a03a6f409`，Android run `39008214906`）在模板报告导出时失败。日志显示模板完成后，后台线程遍历仍由路由回调修改的 JSON 数组，触发 `ConcurrentModificationException`，使报告无法落盘。该次结果不作为发布通过依据。

测试夹具改为在回调线程中、销毁浏览器前序列化完整报告，后台线程只写入不可变字符串。产品代码和报告校验条件保持原样。修复后重新执行源代码绑定的构建和完整 Android 回归，最终结果以 2.0.8 发布验证记录为准。

第二次回归（源码 `c482755d5f0a18a89233c2ada409590f16db6ca3`，Android run `39011178278`）在中文组合输入中观测到 `ni` 没有被 `你` 替换，形成 `ni你`，该次输入结果不合格。继续排查发现 Gecko 的回执路径先 `poll()` 再处理动作，存在队列已空、组合区间尚未复制完成的窗口。

`tools/gecko/run_reply_handoff_host.py` 从官方源码和候选源码提取实际 `notifyIME`、`icSyncShadowText` 方法，通过线程屏障复现提前同步；修复使用 `peek()` 保留待处理动作，处理后只移除原动作。单动作、追加动作及清空后追加动作三种场景均通过受控检查。该检查使用 Android 依赖替身，证明队列时序问题，不能单独证明中文输入问题已完全修复；完整 Android 编辑验收仍为发布前条件。`pocket2` SDK 保持原生和资源文件及其他 Java 类不变。

第三次回归（源码 `4dade3659773d382bfeaa78d60d9c7144c2d8772`，Android run `39012796945`）通过 129 项输入兼容检查、161 项编辑场景、161 项网络场景以及分享、外观和通知检查，但在第二个屏幕宽度的阅读检查失败。截图显示页面已经绘制；旧失败事件没有保存网页测量值，无法仅凭该事件确认是哪一个条件失败。

阅读检查此前把网页 `devicePixelRatio` 当作原生 CSS 到屏幕像素的变换。该值可能被取整或受隐私策略影响（首个宽度的实际 DPR 为 2.608695652173913，Android 420 dpi 对应 2.625），不能据此断言物理宽度。测试现改为读取 Gecko 实际绘制矩阵，保留同一请求、已绘制、宽度误差小于 5 像素、100% 缩放、草稿与布局断言；失败时保留完整测量值。此变更仅在测试夹具内，未调整产品缩放行为。第三次失败保留，不计入发布通过结果。
