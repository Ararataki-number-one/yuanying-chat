# Existing Gecko TLS protocol capability diagnostic

This is a standalone test-package probe of the existing pinned Gecko157 binary and public `GeckoPreferenceController`. It adds no production TLS setting, browser admission bypass, SDK replacement, debug port, TLS interception of user traffic, TLS1.0/1.1 option, or arbitrary TLS fingerprint simulation.

The Android fixture records actual DEFAULT and USER values for `security.tls.version.min/max`, reads RFP and HTTP/2/HTTP/3 settings without changing them, and navigates four unique controlled TLS authorities. The sequence is native default → TLS1.3 only (`4/4`) → exact original DEFAULT/USER restoration. The test peers require TLS1.2 for the first, second and fourth trials, and TLS1.3 for the third. The second trial requires both a native SSL error and a real peer protocol rejection, rather than a timeout. Initial defaults/USER values outside the tested modern protocol range produce a failure; unsupported results are not converted into success.

The host independently records the original bounded ClientHello handshake bytes, SHA-256, random, supported versions, SNI and ALPN offers. Offline replay parses the original handshake bytes again. Successful trials additionally require real negotiated TLS/ALPN, a fresh non-resumed session, a nonce/source/trial-bound HTTP request, and the exact native leaf certificate without a certificate exception. Successful native target admission also requires the same session’s exact target URL/start and controlled trial/nonce title callback. SDK stop callbacks have no URL, are counted only for diagnostics, and never prove target completion or strict-protocol success. Distinct authorities, client randoms, disabled server tickets and rejected PSK offers prevent a cached connection from standing in for a new handshake.

The host serves only two existing synthetic test domains and never forwards traffic upstream. Temporary CA/private keys remain under host `/tmp`; only the public CA is installed in the controlled emulator user CA store. Existing domain-scoped integration trust and test-only enterprise-roots setup are used. The native trust setting is restored; the runner finally stops and clears the integration package, removes its ADB reverse and exact temporary public CA, restores shell UID2000, and deletes all temporary private material. No key is part of an APK or published diagnostic artifact.

`diagnostics/native-tls-*` uses a read-only build → actual API35/four-CPU workflow. Source/tree/run/attempt, APK, SDK, raw device report and independently captured host wire are bound together. Actual DEX/merged-manifest checks require both diagnostic components in the integration package and absent from the release package. Artifacts contain bounded public JSON and the unchanged SDK classpath only.

`tests/native_tls_probe_test.py` runs real **host OpenSSL** peers and parser/false-proof controls. These checks and actual SDK/API source compilation are not Android or Gecko execution. Android capability is established only by the source-bound raw diagnostic workflow and selected-source replay. Neither stage establishes production per-environment integration, HTTP/2 transport, HTTP/3/QUIC wire behavior or complete TLS fingerprint protection.
