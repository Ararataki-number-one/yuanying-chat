# 2.0.18：输入恢复与日常操作体验

候选版本，versionCode 71。基于正式版 2.0.17 整合后续体验修复；完整 Android 验收及正式发布尚未完成。

- 网页实际错误区域出现 `Browser app server websocket failed` 时能够识别；正常对话、历史和代码中的相同文字继续排除。
- “保存草稿”开关作用于本机未发送草稿的持久化、归档和自动恢复。关闭开关保留已有历史，重载前临时采集与防丢确认继续有效。旧浏览器检查点在开关变化后仅过滤表单内容，保留历史和滚动位置；不改变官方网页的登录、Cookie 或网页存储。
- 下载操作区分继续保存、真实续传与重新下载。只清理用户明确选中的失效部分副本，保留任务所有权、活动写入和发布保护，不删除实际保存目标。自动关联后续网页点击、按期限批量清理尚未实施。
- 下载页的“保存位置”按钮按当前字号计算宽高，保留完整标签和原有最小触区，改善大字号下的截字问题。
- 环境仍可用但网络快照过期、缺少有效时间或身份不符时，显示“状态待核实”，避免误标为“未运行”。同一身份的旧 IP 和延迟仍按原规则标为“上次”；跨身份旧读数的完整拒绝与网络、网页状态分层仍待后续处理，不能把此项当作整个 N15 已完成。
- 删除默认环境时在原事务内选择真实可用环境；重置期间的临时回退不会替换原默认。修复旧默认指向已删除槽位及槽位复用后的误选，保留原有最后环境保护。

本候选对应 N05、F04、M01、F06 和 N15 的上述有限范围。主机验证、语法检查与实际 Android 验收分别记录，不能将候选代码或主机通过当作真机通过。2.0.17 的分享、设置回执及全部原门禁继续保留；未合入性能索引改动，也没有新的提速结论。

此前 `3eac289` 的设备验证仍失败：草稿关闭后的恢复等待超时，普通输入的固定手势时隙失约，原十项最终检查未执行。旧失败原件保留；后续源码增加有界、只读的草稿恢复失败观测，原超时与验收条件不变。这些观测尚不能作为根因修复，必须由新一轮完整同源码验证决定验收。
