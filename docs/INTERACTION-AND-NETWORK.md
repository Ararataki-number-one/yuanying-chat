# 交互规则与网络优化方向

## 页面层级

默认页面先展示名称、当前状态和主要操作。会话顶部使用单行工具栏，网站域名放在环境名称下，显示方式点开选择，网络状态只在未连接或有变化时展开。合并重复标签和只读信息，分组排序、备注、浏览器参数、保存位置、日志等点开查看。手机网络模式隐藏不适用的订阅与线路分页。必要按钮保持容易点击，节省空间靠减少重复内容。

## 使用时应能回答的三个问题

现在处于什么状态？接下来做什么？返回或关闭会发生什么？界面围绕这些问题组织提示与操作，避免只暴露底层功能入口。

| 场景 | 交互规则 |
| --- | --- |
| 填写 | 主操作靠右或独立显示，次操作靠左；新建分步说明；校验在错误字段旁提示，保留已经填写的内容 |
| 返回 | 多选先退出选择；新建先回上一步；有修改的环境编辑、网络、启动设置及分组表单先询问如何处理；网页管理页返回会话 |
| 等待 | 无真实百分比时使用等待指示；弹窗说明收起后继续，可重新查看；避免重复提交同一网络操作 |
| 完成或失败 | 会话内管理页保留错误直到关闭，完成提示短暂显示；表单失败保留内容，给出修正位置；保存简单资料后提示完成 |
| 列表 | 刷新保留位置；主动更改下载筛选从顶部查看新结果；空状态说明原因并给出可用下一步 |
| 操作触达 | 原生管理按钮、分页和返回按钮至少 48dp；显示按下、选择和禁用状态；创建与编辑的底部操作固定 |

本轮已应用到环境管理、新建、环境编辑、网络参数、节点测速、下载和应用设置。真实手机上的手势返回、输入法和 WebView 页面仍需按验证清单复核。

## 网络下一轮优先级（规划，尚未实现）

已有手机网络 / VPN、应用代理、单订阅 + 固定出口、完整链路探测、成功率与波动统计、自动恢复、固定出口核对和事件记录。下一轮应让这些能力更易判断和恢复。

| 优先级 | 用户需要 | 建议方向 |
| --- | --- | --- |
| 1 | 知道为什么不能用，以及先做什么 | 统一连接阶段和错误：手机网络、订阅、入口、固定出口、网页分别显示真实检查结果和时间；失败项提供对应修复入口。分项 DNS / TCP / TLS 诊断需补测量实现 |
| 2 | 点一次就能按合理顺序修复 | 引导检查手机网络、核对配置、重连和确认出口。解释每一步结果，不重复发送聊天；已有恢复逻辑与按钮统一呈现 |
| 3 | 线路稳定、选择容易理解 | 暴露手动固定入口 / 自动选择偏好，说明当前入口的实际延迟、近期成功率、最近失败和自动切换原因；延续当前冷却与忙时限制 |
| 4 | 更新订阅时更放心 | 展示节点数量、上次成功更新时间和缓存状态；更新失败时解释是否还能使用缓存。配置测试通过再替换、失败回退需要实现事务流程 |
| 5 | 区分出口保护的实际覆盖范围 | 独立呈现出口变化、VPN 断开和检查过期；DNS / WebRTC 等泄漏检测只在完成对应检测后显示结果，公开服务检查由用户主动发起 |

先做 1 和 2；用户能看懂连接问题和恢复步骤后，再扩展多订阅、带账号密码的外部代理等能力。多订阅和外部代理认证涉及凭据、迁移和链路约束，应独立实现并验证。
