# 完整界面验收的报告与作业预算

五页界面共用原 Android UI 验收流程：111 张基础截图、字号与主题组合、紧凑工具栏、网址输入、网络分享、原生外观与网页外观检查。发布资格仍来自同一源码、安装包、工作流运行与尝试的全部 13 项作业及最终证据检查。

## 完整 JSON 报告的排版

最终的 `compact-chrome-results.json` 和 `ui-visual-results.json` 使用紧凑 JSON 排版。这个变化只去掉 JSON 值之间用于阅读的缩进与空白，不删字段、场景、断言结果、采样或原始事件。`rawUtf8`、XML、Activity 状态等字符串内部的内容和空白继续保留，原事件字节数及哈希校验照常执行。中途截图检查点及原始捕获文件继续沿用各自原格式。

原发布器和 CI 封装器仍扫描完整报告，继续执行原有的 16 MiB 单文本文件上限、编码检查和敏感内容检查。紧凑排版后的报告仍可能超限；这种情况必须失败，不能截断报告、跳过扫描或将不完整报告标为通过。

[42800077619 / attempt 1](https://github.com/Ararataki-number-one/yuanying-chat/actions/runs/42800077619) 的主 UI 作业在发布与封装阶段触发了这一大小限制。该次主 UI 最终 ZIP 没有生成，不能据此补造最终报告或认定整个 UI 套件通过。同一源码的已取得冷启动工具栏诊断报告为 18,692,898 字节；保留全部解析值的紧凑表示为 12,852,631 字节。这只验证排版能减少体积，不替代新源码的完整 UI 报告与发布检查。

## UI 作业的外层运行时间

Android 矩阵中的 `ui` 作业使用 60 分钟总预算，其余 `editing`、`files`、`connections`、`profiles` 四项仍为 40 分钟。这个总预算包括准备模拟器、运行全部 UI 用例、发布检查点以及封装、上传证据。各个准备步骤、输入操作、截图、性能检查和 reader 自身的截止时间、阈值、采样数及失败行为保持原样。

上述旧 UI 作业从开始到结束共 40 分 17 秒。主 UI 步骤开始前用了 2 分 46 秒；该步骤用了 33 分 15 秒，网络分享与原生外观步骤又用了 3 分 5 秒，网页外观步骤启动时距原 40 分钟边界只剩 54 秒。网页外观步骤运行 67 秒后仍未记录完成，随后日志出现取消。时间与原总预算吻合，但日志没有说明取消操作者或确切触发机制。

为完整套件分配更长的外层作业时间，不授予任何失败用例资格。新的真实工作流必须完成全部用例与证据封装，保留原隐私检查，并重新通过所有发布门槛。
