# 网络状态缺失的最小展示修正

这次只处理 N15 中一个确定问题：环境仍可用，但运行快照过期、缺失或
与当前环境身份不符时，原来统一显示“未运行”。现在显示“状态待核实”；
确认没有运行环境时继续显示“未运行”。未配置状态的优先级保持不变。

没有有效时间的快照不能表示已连接。有效时间必须大于零；45 秒的新鲜度
边界及原有最多未来 60 秒的时钟容差保留。容差以内仍须满足全部原连接、
健康与出口规则，容差本身不构成联网证据。

同一身份但快照过期或缺少有效时间时，旧 IP 和正延迟按原规则标为“上次”，
测速倒计时显示“等待连接”。这只是读取模型的展示变化，不连接服务、
切换入口、刷新网页或修改会话数据。

“可用”由调用方提供：网络列表检查本应用 UID 下的精确环境进程名；
当前聊天使用已有会话及目录环境的 UUID、代次和可用性。这个布尔值
不能证明线路已连接。此次没有增加快照 PID 与当前进程的关联校验，
没有改变旧无身份快照的兼容规则，也没有完成手机网络、本地服务、代理
与网页状态的全部分层或证据时间展示，不能视为完整 N15 已完成。

身份不符时，旧实现仍可能显示该不符快照的 IP 和延迟。这次只确保
“状态待核实”、未连接及等待倒计时，不将这些值当作可信的历史样本。
测试原样保留其读数，但不要求继续显示这些跨身份数据；完整拒绝跨身份
展示是后续独立修复，位置在 `WindowNetworkState` 的 `ip` 和 `latency`
赋值处，不能以此次状态文案修正宣称已解决。

宿主回归执行实际构造器、主行显示和顶部栏元数据路径，覆盖新鲜度、
身份、健康、出口及原有显示规则。设备网络测试追加 14 个明确标为受控
投影的输入/输出用例；原检查和实际线路计数保留。投影中的 42 ms 是
固定展示数据，不是真实延迟。宿主通过后仍需所选源码 APK 的 Android
流程通过；此文档不代表已经取得设备、真实线路或真机验收。
