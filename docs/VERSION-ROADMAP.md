# 版本基线与分阶段交付

已发布基线为 `v1.5.23-gecko`，源码
`6a1bab77f1bcc70f0fc4f990b287fec08ec54412`。上传的评审包基于这个版本，
不是基于旧 main，也不是三个已经验收的正式版本。当前下载文件和更新安装包
删除功能使用 1.5.24 / code50；后续版本在其基础上合入，保留删除、双订阅、
连接预认证、页面缩放、登录目录及草稿修正。

| 阶段 | 版本编号 | 交付重点 | 正式发布前的验证 |
| --- | --- | --- | --- |
| 当前 | 1.5.24 / 50 | 实际下载文件、更新安装包清理与错误反馈 | 原有 Android 回归及删除专项检查 |
| 第一阶段 | 1.6.0 / 51 | 网络恢复判断、可靠配置意图、独立订阅、版本化环境模型 | 原有回归、新模型与恢复检查、用户 ARM 真机清单 |
| 第二阶段 | 1.7.0 / 52 | 少量已验证模板、期望与应用及观测状态、环境生命周期 | 真实 Gecko 页面、iframe、Worker 与请求头；用户真机兼容性 |
| 第三阶段 | 2.0.0 / 53 | 通过验证的必要能力、资源与内核维护策略 | 能力对应的实际观测、持续使用与升级演练 |

所有版本保持单 GeckoView、ChatGPT 原网页、独立环境、入口与固定出口分开
管理，以及安静的正常操作。附件中的源码、主机报告和文档先作为评审材料，
修改后重新构建和验证，不沿用旧报告作为新候选的执行证据。

## 候选与正式发布

候选版本使用 `v版本-candidate序号-gecko`，在 GitHub 标记为预发布，提供
原包名、原签名的安装包。候选不会推进正式自动更新地址。正式版本继续使用
`v版本-gecko`；每个已发布标签的源码、清单和安装包不可替换。

1.6 起由用户安装候选包并按清单进行 ARM 真机测试。人工检查记录绑定该
安装包哈希、源码、版本、设备和检查项，明确标记为用户报告，不冒充自动化
Android 证据。检查失败先修复并交付新的候选，再决定正式发布。

## 能力原型与支持范围

1.6 的官方 SDK 原型仅记录受控页面、同源 iframe、Dedicated Worker 和
实际 HTTP 请求头，以及运行时与会话设置的作用范围。独立时区、其他 Worker
种类、真实账户、RFP 兼容性和跨进程环境隔离分别记录覆盖情况。
原型通过不等于 1.7 指纹模板已通过验证。

模板自检必须能区分未观测、观测不一致和已验证，不能因为缺失字段被当作
默认值相等就判为成功。只有官方 SDK 实际接受且网页或服务端已观测的能力
进入相应支持范围。

2.0 首先检查官方接口与上游方案；必要原生增强逐项验证。未实现或未通过
验证的自定义时区、Canvas、WebGL、音频和字体控制保持未支持。继续使用官方
GeckoView 的回退方案可以交付已经通过验证的维护和资源改进。
