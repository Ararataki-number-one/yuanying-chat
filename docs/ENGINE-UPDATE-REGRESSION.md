# 内核更新与阶段稳定版回归

构建工具、固定 SDK 输入、签名和 APK 检查沿用 [BUILD.md](BUILD.md)。下面补充每次内核升级与阶段收尾所需的记录顺序。

1. 记录上一正式标签、候选源码提交、SDK 坐标与上游 revision。检查 Mozilla 对应版本的安全更新说明；在同一候选中更新官方 AAR、POM、源码包的来源记录和校验和，以及实际适配的源码。发布采用单 GeckoView、官网输入与固定出口。
2. 复核 `third-party/gecko/GeckoEditable-native-caret.patch` 对新上游源码的适用性。通过 `tools/gecko/caret_workflow.py prepare` 重新生成派生 SDK 和来源收据；核对当前配方、解析后的实际 AAR、APK 内嵌 SDK 身份及应保持不变的载荷。具体输入与输出以本轮构建记录为准。
3. 先运行修改涉及的主机检查，再对同一源码与同次构建完成当前 Gecko 工作流规定的全部门禁。保存原始失败记录并定位原因；源码修改后重新建立候选身份。受控 Android 回归需要保留登录隔离、输入、草稿、缩放、附件、下载、恢复和网络保护的原断言。
4. 在同一真实手机上固定系统、输入法、内核、来源、网络和聊天规模，分别记录标准与确认后的强化模式。登录、百度输入法、组合输入、长聊天滚动、附件、下载、切网及前后台恢复逐项记录。没有运行的项目保留“未验证”，主机或受控 Android 结果分别注明来源。
5. 发布前用原证书核对覆盖安装资格、正式包名、versionCode、16 KB 对齐及测试入口排除。发布后重新下载公开 APK，验证签名、字节摘要、版本、来源标签和更新入口。详见现有发布脚本与当次回执。

## 诊断副本

自检的简要结果、深检诊断和双报告诊断采用固定字段投影。复制内容包括有限状态、数值及编码有效的操作哈希；任意 UA、来源地址、IP、原始错误和网页文字不进入这些副本。哈希编码有效只说明格式符合要求，不能认证操作、保护效果或真实设备身份。

本机原始对照字段仍可展开查看；原始记录及配置文件不作为诊断附件。耗时与网络事件诊断沿用固定状态、数值和受控事件日志。备份文件、代理或订阅密码、Cookie、聊天正文、草稿、附件路径及设备密钥不属于诊断副本。

新增执行环境或检查项时，先审计原始数据来源，再明确扩展投影的有限字段和边界测试。未列入投影的字段保持省略；不把整个新对象直接传给剪贴板。

## 阶段收尾记录

逐版合入后核对环境身份、保护确认、线路、网页和发送结果入口；高级检测与原始字段继续按需展开。检查配置备份、站点权限、后台执行环境等新增入口的归属与错误提示，复跑与合并冲突相关的原测试。清理入口继续说明实际处理范围并保护正在使用的数据。

本次准备尚无真实手机兼容结果：登录、百度输入法、附件、长聊天帧耗时、切网和锁屏恢复均待现场验证。后续应附实际报告来源、设备与版本、复现步骤、结果和剩余限制，逐项更新记录。
