# Gecko 独立时区的原生边界

本功能使用当前 Gecko 既有的 `BrowsingContext.timezoneOverride`，不替换内核、
不修改 SDK/AAR 的字节，不更改 Android 时区，也不重写页面 `Date` 或 `Intl`。
设置回读与实际网页、Worker 的观测分别记录。没有真实 Android 报告时，不能
把主机测试或属性回读描述为全部执行环境已经采用独立时区。

## 配置与加载

每个环境保存独立的加密时区配置，可选择系统、UTC 或 IANA 地区时区。
原模板的期望／已应用版本没有被复用为时区确认。原生确认绑定环境身份、
配置修订、实际 SDK 会话 ID、唯一打开代次、浏览上下文 ID 和请求 token；
旧进程或已关闭上下文的回执只保留为历史。

应用自己打开的主会话、重建会话和辅助 IP 页先等待 SDK 窗口就绪，再通过
私有原生端口读取准确上下文、应用设置并保存严格回读，之后才首次导航或
恢复 SDK 状态。异步检查、状态过滤和端口更换后都再次核对门禁。等待期间
只保留每个会话最新的导航目标，不重复发出已被替换的加载。

原生接口不支持时，默认系统模式可以继续原有行为，但不标为原生确认。
自定义时区失败则暂停新加载，并显示失败原因；可以明确切回系统模式恢复。
Firefox 强化保护与自定义时区冲突时保留强化保护，不静默降低保护等级。

## 私有接口

应用自带扩展的实验 API 仅位于 `addon_parent`，限定固定扩展 ID 且必须为
privileged。会话匹配使用 SDK 的实际 session ID 对照原生窗口名称，不猜测
标签编号或窗口数量。消息只经当前私有 host 端口处理，不注册网页或内容
脚本的时区消息通路。

Java 与扩展分别核对请求、端口及严格的原生回执。取消、关闭、配置变更或
端口替换会退役旧确认；能力报告动态读取当前上下文状态，不能沿用旧回执。

## 弹窗与输入保护

当前 SDK 要求 `onNewSession` 返回尚未打开的会话。提前打开并等待时区确认
违反接口要求；等待一个尚未创建的原生窗口也会互相阻塞。因此自定义时区
暂时明确拒绝新弹窗。系统模式保留原弹窗流程，不声称独立时区已确认。

用户应用配置前会检查已知任务，并明确确认重新加载及关闭现有弹窗。
ChatGPT 页面继续执行原有任务与草稿核对；普通网站不注入 ChatGPT 检测脚本，
而是明确要求用户手动保留表单。既有 SDK 状态仍经原来的草稿保存策略过滤
后恢复，不自动提交内容。

## 验证范围

主机测试执行真实路由、加载及恢复方法和真实扩展脚本；SDK、浏览器、原生
窗口和控制器边界均明确声明。它们不代表 Android 原生 API 已成功激活，
也不证明 `Date`、`Intl`、Dedicated／Shared／Service Worker 的实际时区。
这些结果必须由同源码的独立 Android 观测与服务端证据确认。

当前内核的独立原生能力探针已观察到页面、Dedicated、Blob 和 Shared Worker
跟随纽约及加德满都时区；Service Worker 仍读取系统时区。系统本来为 UTC
时的偶合结果不能算作 Service Worker 隔离成功。产品界面明确保留这一缺口，
原生设置回读与每种执行环境的实际效果仍分开报告。

新增生产验收流程使用真实 MainActivity 的时区和模板编辑器保存配置，并分别核对
首个内联脚本、HTTPS 服务端请求头、私有当前上下文读取、重载与 SDK 表单
恢复。跨源 COOP 导航如实记录上下文是否替换，不把未发生的替换声称为覆盖；
应用主动重建与恢复用例仍要求新的原生上下文。它与原有验收同时必需，不能
用能力探针或主机合成报告代替生产界面验收。
