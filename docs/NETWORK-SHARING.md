# 入口、出口与线路分享方案

状态：2026-10-16，首期单入口、单出口与整条线路分享已随 2.0.5 正式版发布。构建、lint、Android 回归与公网下载校验通过；跨手机真机验收尚未完成，见 [验证记录](VALIDATION-v2.0.5.md)。

首期实现：文件/复制、导入预览、保存本地库、选择已有环境、现有编辑器显式应用。多入口勾选、分享订阅地址和导入时新建环境留待后续；下文是完整设计，不能把后续选项视作本版已提供。实际范围见 [2.0.5 发布说明](RELEASE-v2.0.5.md)。

目标：用户把自己的入口、固定出口或整条线路发给同样使用本应用的人，对方无需重新填写服务器、端口和账号。沿用单 GeckoView、ChatGPT 原网页、独立环境和安静操作的产品定位。

## 2.0.5 实际操作路径

- 分享入口：网络 → 入口 → 打开订阅详情 → 查看节点 → 节点右侧 ⋮ → 分享入口。
- 分享出口：网络 → 出口 → 固定出口右侧 ⋮ → 分享出口；出口订阅中的节点也可从“查看节点”的更多菜单分享。
- 分享整条线路：网络 → 窗口网络 → 环境卡片 ⋮ → 分享整条线路，使用当前生效入口与固定出口。
- 接收：网络右上角 ⋮ → 导入网络 → 选择文件或粘贴 → 预览 → 导入并选择环境 → 保存并应用。双方使用 2.0.5 或后续兼容版本。

打开预览或选择环境不会直接更换网络；取消应用保留当前线路。若只保存到网络库，稍后可在环境网络编辑器中选择。

## 操作位置与默认行为

| 位置 | 操作 | 默认内容 |
| --- | --- | --- |
| 入口节点的更多菜单 | 分享入口 | 当前选中的入口节点 |
| 固定出口的更多菜单 | 分享出口 | 当前固定出口，含必要连接凭据 |
| 窗口网络卡片的更多菜单 | 分享线路 | 当前已应用的入口与固定出口 |
| 网络页的更多菜单 | 导入网络 | 打开分享文件或粘贴分享文本 |

不在每张卡片上新增常驻分享按钮。分享使用中央 Modal，展示名称、入口/出口摘要及“取消 / 分享”。系统分享面板用于发给其他人；应用不自动发送消息。

分享线路弹窗提供三个选项：“仅入口 / 仅出口 / 入口和出口”，从窗口卡片进入时默认第三项。默认只分享当前生效的配置；如有未应用修改，用一行注明“分享当前正在使用的线路”，避免把草稿当成可用线路。

入口默认分享当前节点；用户可展开“选择更多入口”勾选节点。只有实际包含了完整候选池时才允许保留自动优选/随机策略，否则导入为手动指定当前节点。固定出口始终固定，不参与随机。

“包含订阅地址”单独放在展开选项，默认关闭。开启后接收方获得该订阅的后续更新访问能力，弹窗就地说明这一点；不能把只分享一个节点变成默认分享整份订阅。

## 分享载体

首期以 `.pocketnet` 配置文件为主，通过 Android 系统分享；单节点另提供“复制配置”，接收方粘贴导入。文件可直接通过本应用打开，也可在网络页选择导入。导入页面只解释要新增哪些入口、出口和线路，不展示 JSON 或技术字段。

文件默认包含连接所需的账号和密码，分享弹窗用一行说明“包含连接账号和密码”。这是可导入配置，不宣称普通文件或 Base64 文本具备加密保护。本地入库继续加密存储；临时分享文件放在独立缓存目录，通过 content URI 临时只读授权，按保留期清理，不能在系统分享面板刚返回时立即删掉而导致对方读取失败。

二维码可作为第二阶段的便利入口：只用于容量合适的单节点；过大的节点池明确引导使用文件，不截断。首期无需建立云分享服务器，不设计无服务端支撑的到期、撤回或一次性访问承诺。

## 接收方流程

1. 打开文件或粘贴配置，本地解析后展示“入口 N 个 / 固定出口 N 个”和线路方向，不立刻联网或切换环境。
2. 默认“保存到网络库”；另可选“导入并配置环境”，再选择已有环境或新建环境。
3. 只有入口时，仅填充环境的入口候选，保留已有出口；缺少出口时引导选择。只有出口时反之。不静默补成直连。
4. 选择完整线路时，生成该环境的候选配置。点击“保存并应用”才验证和应用；正在回复、上传或下载时沿用现有延后应用流程。
5. 失败在当前弹窗说明原因并保留原线路；成功直接返回列表，不额外弹成功提示。发送方的“已核验”、延迟和地区观测不能当作接收方的验证结果。

同名不代表同节点。重复导入相同内容可复用原记录；同名但服务器、协议、传输参数或凭据不同，应创建新记录，不覆盖已使用的节点。凭据变化不能仅按服务器地址去重。固定出口的实际地址需要接收方重新核验。

## 数据契约与代码分工

采用版本化白名单格式：`format=pocketchat-network`、`schemaVersion=1`、`kind=entry|exit|route`，包含名称、入口节点、固定出口及包内线路引用。定义文件/文本大小、节点数量和字段长度上限；不导入任意 Mihomo 脚本、规则、监听端口或外部文件引用。

包内 ID 只用于关联此次分享中的节点。导入时建立新的本地稳定 ID 与引用映射，不继承发送方的环境 ID、存储路径、校验通过状态、缓存槽位或本机密钥。节点协议与参数沿用已支持的入口解析和校验；首期出口保持 SOCKS5。未知版本或不支持协议给出可读错误，不能静默丢字段后应用。

- `NetworkShareCodec`：白名单编码/解析与版本限制，保留完整必要协议参数；日志和错误不输出密码或订阅令牌。
- `NetworkShareUi`：导出选择、导入预览和环境选择，中央 Modal。
- 分享文件 Provider：仅暴露独立分享缓存，使用临时读取授权；不开放环境存储或整个缓存目录。
- `NetworkCatalog`：复用入口/出口角色、稳定引用和加密存储。增加明确的本地分享来源类型（无订阅 URL）；不能虚造 HTTPS 地址套用远程订阅。远程订阅仍按用户显式选项保存和更新。
- `NetworkDraft`、`NetworkChanges` 与现有环境配置协调器：候选、验证、延后应用及回退。导入库本身不重连运行中的环境。

本地分享来源使用节点配置快照，不显示“更新订阅”；带有效订阅地址的来源可更新，但固定出口选择仍遵循现有稳定 ID 与凭据修订规则。分享的节点清单与订阅更新后的清单差异应按现有选择失效规则处理，不自动改用其他出口。

多项导入需要一次校验、原子提交或可恢复事务；中途失败不能留下只导入入口但线路引用丢失的半成品。导入前不下载订阅，不执行测速；任何联网均由用户保存订阅更新或应用线路的明确操作触发。

## 验收顺序

1. 实现并验证单出口分享/导入，再实现入口节点，最后组合线路与多个入口。覆盖复制文本、系统文件分享及其他应用打开文件。
2. 两台 Android 设备验证三种分享方式、重复与同名导入、特殊字符/Unicode/空密码、取消导入、未知版本和损坏文件。
3. 验证不包含 ChatGPT Cookie、登录、聊天、草稿、环境私钥或无关订阅；文件读取权限不越界，取消与过期缓存可清理。
4. 验证生成回复时导入不打断会话；未点击应用不更换路线；应用失败保留旧配置；接收方重新核验出口且不会复用发送方的可信状态。
5. 验证新增/编辑出口默认可见、隐藏/显示不改密码或光标、长密码可横向编辑、小屏和大字号下按钮不遮挡输入。

发布前编译并完成对应 Android 测试，真实跨设备验收单独记录。
