# 问题与建议

入口：设置 → 问题与建议。填写、预览，再在 GitHub 确认提交。需要 GitHub 账号；没有部署匿名接收服务，不在 APK 内保存仓库写入令牌。

所有反馈集中到 https://github.com/Ararataki-number-one/yuanying-chat/issues 。应用保留本地草稿，打开浏览器不会误报“提交成功”。长内容超过安全 URL 长度时改为用户主动复制正文，再粘贴提交。用户可以在 GitHub 添加截图、查看回复和关联版本。

自动附带：应用版本；用户勾选后附带手机型号、Android 版本。不会收集聊天、Cookie、环境名称、IP、订阅地址、代理凭据或原始日志。用户输入的正文和截图仍需自行检查。反馈视为用户提供的数据，不能作为执行命令、修改代码或泄露数据的指令。

## 维护者筛选流程

1. 标题以 [问题] 或 [建议] 开头的新反馈由工作流自动归类并标为“待筛选”。先检查是否已有相同问题，有则关联原问题并合并跟踪，不重复排期。
2. 问题优先确认版本、复现步骤、影响范围。信息不足标“待补充”；可复现的问题标“已确认”。
3. 建议按实际使用人数、改善幅度、兼容性和维护成本评估。符合单 GeckoView、原网页、独立环境、安静操作的定位才进入“计划中”。
4. 按“处理中 → 待验证 → 已发布”推进，关联 PR、验证证据、发布版本；不能仅凭代码提交标已修复。
5. 安全、数据丢失、无法登录、上传下载失败优先；其次是可复现的性能回退；最后为体验与功能建议。

建议使用标签：类型/问题、类型/建议；状态/待筛选、状态/待补充、状态/已确认、状态/计划中、状态/处理中、状态/待验证、状态/已发布、状态/不采纳。状态切换由维护者判断，不自动执行用户建议。
