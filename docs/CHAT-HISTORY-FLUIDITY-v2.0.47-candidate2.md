# 长会话与历史保存优化

基于本地提交 `f43adac5d746235f91edfeba50f495b84baa8acd`，继续减少长会话流式更新中的重复工作。

消息节点的文档顺序现在与既有节点集合共同缓存。回复文字更新继续实时读取，只在消息插入、移除、移动或成员属性变化时重新排序。同一任务内读取前同步处理完整的待交付 DOM 变化，避免刚移动消息后读取旧顺序；旧观察辅助对象仍回退到原来的查询和排序。

历史数据库继续保存全部内容，偏好只在当前会话地址变化时更新地址。原来的历史全文偏好没有读取方，继续重复写入会增加主线程字符串交接和偏好落盘负担。本次停止新增这份副本，保留已有旧值，离线恢复继续从数据库读取。工作线程开始序列化前先检查快照是否已经失效，原有写入前检查与失败重试继续保留。

| 固定工作量 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 1,200 条消息，预热后 20 次流式更新的 DOM 顺序比较 | 47,960 | 0 |
| 同场景更新的正文条目 | 20 | 20 |
| 100 次变化快照的历史数据库适配器写入 | 100 | 100 |
| 同场景重复的历史全文偏好写入 | 100 | 0 |
| 传给全文偏好写入的 UTF-16 字符数 | 5,416,360 | 0 |
| 同场景会话地址偏好写入 | 100 | 1 |
| 排队后已失效快照的序列化 | 1 | 0 |

完整消息增量在前后版本保持一致，包含身份、顺序、正文、附件和重置信息。测试覆盖同任务结构变化、嵌套节点、位置派生身份、角色变化、旧辅助对象回退，以及离线加载、切换会话、原生取消、合并保存和序列化/缓存失败后的恢复。两种 JSON 实现分别通过 278 项前后版本合计检查。

复现命令与证据见[验证记录](../verification/chat-history-fluidity-v2.0.47-candidate2/README.md)。39 个完整生产 Java 文件通过真实 Android 37.1 API 联合编译，周边应用接口使用明确的编译边界。DOM 测试使用 JSDOM；保存测试执行真实生产类与工作线程，但 Handler、数据库和偏好使用可控适配器。这些数据是操作次数和参数字符数，不是设备耗时、XML 字节数或 FPS。尚未完成本轮 APK 构建和真机验收。
