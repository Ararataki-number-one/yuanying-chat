# 1.5.19 · 聊天交互与更新续传

用户报告聊天输入、滚动卡顿，以及 APK 下载速度慢且中断后无法继续。此次优先处理已经从代码和受控负载确认的应用侧负担，避免把手机与电脑的线路差异当作软件提速证据。

| 文件 | 修改与作用 |
| --- | --- |
| `AppUpdateTransfer.java` | 将完整版本身份与持久化部分文件绑定，按 HTTP Range 续传；核对 Content-Range、大小、强 ETag 与编码，重新获取官方 HTTPS 跳转。完整文件仍必须通过 SHA-256 和 APK 身份核验。 |
| `AppUpdateManager.java` / `AppUpdateJob.java` / `AppUpdates.java` / `AppUpdateProvider.java` | 将下载与状态控制分到不同线程；持久化下载意图和暂停状态，由系统任务处理网络约束与恢复；保护旧任务与新任务之间的所有权。暂停、取消会使已排队和正在准备的旧下载命令失效，旧系统停止回调不能作废新的继续命令。取消清理使用独立持久标记；即使清理前进程关闭，重启也先删除已取消片段，避免把它当作可续传进度。保留旧 DownloadManager 完成路径，迟到的进度查询必须仍属于同一任务，不能覆盖取消后的状态。 |
| `AppUpdateActivity.java` | 提供暂停、继续、取消确认、实际速度与剩余时间。进度刷新保留原有控件，避免每秒重建整页。 |
| `GeckoWebView.java` / `BrowserSessionStore.java` | 减少未改变位置和安全区时的重复原生表面同步；将 SDK 明确支持跨线程的会话序列化与文件保存移出主线程，合并等待写入的最新快照。后续无效快照仍保留最新有效候选，持续更新时也定期原子落盘。 |
| `ChatSession.java` / 网页观察脚本 | 减少持续输入与滚动期间的长对话抓取；避免一次无关按钮点击扫描整页按钮；合并同批 DOM 失效与重复 resize 工作。保持真实发送捕获、完整回复和附件正确性。 |
| `NativeNetwork.java` / `NetworkRegion.java` | 自动线路与地区探测在繁忙聊天时让位，进入串行队列后再次检查是否已有有效测量；自动恢复入口时去掉同一路线的第二次重复出口核验，发送前核验仍完整执行。核验服务的连接重置和提前 EOF 仅在已有核验凭据、路线与核心生命周期完全一致时保留原长连接，发送前检查仍返回失败。首次连接、换线路、真实核心死亡和出口不一致仍停止。取消、TLS 身份和配置错误不归为服务暂时断开。已开始的探测请求可能继续到原有超时。 |
| `app/build.gradle` | 正式版本更新为 1.5.19 / code 45。 |

主机 HTTP 故障回归与实际 Android 测试覆盖下载中断、暂停与重建、取消清理前杀进程后恢复、范围回退及拒绝异常数据；浏览器测试覆盖输入、滚动、坐标变动与后台最新状态保存；实际 Mihomo 测试覆盖繁忙时避免新探测流量、空闲后真实测量与已有长连接连续通信。核验服务的 RST / EOF 验收要求真实独立服务和同一 WSS 继续收发，并核对 PID、入口、核心代号、控制密钥摘要与端口未改变；同种故障下首次和换路线仍拒绝。发布要求测试记录与 APK 来自同一源码。

续传减少中断后的重复下载，应用侧调度减少资源争抢；这些行为不等同于提高运营商带宽或缩短线路物理距离。受控负载和模拟器数据不能代替用户手机的帧率、真实账号或同线路手机/电脑对比。

[本版完整验证与公网下载校验](../verification/chat-resume-v1.5.19/README.md)已归档。此前正常硬件按键测试出现的偶发光标回退尚未归因，本版正常回归未复现；带原生诊断的三次通过不能证明其已修复，未加入未经验证的 SDK 补丁。原失败与诊断分析分别保留于验证目录的 `known-input-boundary`，不混入正式通过结果。
