## 本轮修复与未发布失败构建

早期主机编译发现界面测试替身缺少新增主题工厂，补齐测试依赖后重新编译。随后 Android 实测发现 Gecko 隔离子进程也会执行 Application 的主题初始化，触发系统禁止其访问设置数据库而无法启动。已将初始化限定在持有应用 UID 的界面进程，非界面／隔离进程不读取主题存储；相关进程范围策略和实际 Gecko 回归重新通过。失败构建未发布。随后原生主题测试在进程重启后读到上次启动的持久化证据，错误地认为实例未变化；改为每次启动传入新随机标记，仅接受新启动的状态快照，保留原有重启持久化与实例变化断言。

## 性能结论与边界

本版改变候选探索与确认顺序、空闲扫描节奏、性能换线冷却和网站探测预算，移除不能调整固定出口解析器的例行 DoH 轮测。延迟口径、固定出口和聊天忙碌保护保持；没有降低显示数字或把入口单测当成完整线路。

受控网络测试在本机 loopback 的两个入口人为设置不同握手耗时，验证应用确实测量不同线路和减少重复请求。该测试不是手机公网基准，首轮 TLS 初始化／复用也影响结果，不能用其中的数值计算本版在真实节点上的提速百分比。只有允许池内存在更好的完整线路，自动优选才可能明显降低延迟；同一固定链路的物理传播时延不能由客户端消除。

真实 ChatGPT 网站主题水合、ARM 手机、系统定时切换、百度输入法、长期后台及真实账号上传下载仍需真机验证。受控 Cookie／草稿保留不等于完成真实账号升级验收。此前快速切换光标后立即输入的间歇性错位不在本版修复范围。

## 手机对比方法

1. 覆盖安装，设置 → 白天与黑夜保持“跟随系统”，切换手机系统深浅色，确认原网页及管理页随之变化且草稿保留。
2. 同一手机、Wi-Fi、固定出口与允许入口池，使用“低延迟优先”；空闲时让优选取得连续样本。手动入口保持手动选择，不会被自动更换。
3. 记录更新前后的相同完整链路测量和 ChatGPT 首响应，冷连接与复用测量分别比较，同时观察断开次数；电脑入口 101 ms、出口 141 ms 的独立读数不能直接代替完整链路结果。
