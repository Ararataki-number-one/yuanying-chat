# 浏览器界面改造

## 基准

本轮从正式标签 `v2.1.4-gecko` 的提交 `7383bb1dd82c5d2155ba7c8dcc11b541478f6cfe` 开始，版本标识仍是 2.1.4 / 106。对应发布分支为 `release/browser-2.1.4-five-page-ui-20261111-r9`。旧的四页交接快照和五页预览只用于核对设计，没有覆盖正式源码。此开发分支不代表已经发布新正式版。

## 使用变化

- 五页导航的“会话”更名为“浏览器”，采用浏览器图标；其余四页继续保留原有功能。
- 点击环境卡片直接打开该环境的浏览器。首次进入仍核对环境身份并先绘制原生页面；切回已有环境继续原网页。环境详情移到卡片的“更多操作 → 环境详情”。
- Gecko 页面常显网址入口，包括 ChatGPT 页面。提供后退、前进、刷新／停止和主页操作。主页默认仍是 `https://chatgpt.com/`，用户已有的主页偏好不被重置。
- 窄屏时地址独占一行，保留原字号与四个完整触控入口。尚未加载网页时使用已有恢复目标或主页作为地址默认值，真实可见的空白页仍保留其实际地址。
- 顶部环境胶囊继续支持点按输入网址、长按切换环境。底部环境、网络、下载保持整体居中，阅读入口独立。
- Chromium 保留真实多标签、书签、历史、页内查找、文件和权限功能，工具区改用同一套浅色玻璃与按压反馈。从环境页重新进入时不再强行打开主页。
- 地址切换与后退只做有时间预算的页面快照，快照不响应也会继续导航；刷新继续使用既有草稿检查和确认流程。普通网站不注入 ChatGPT 专用脚本。
- 横屏等短窗口中，空白页状态提示优先展示标题和实际操作按钮，解释文字继续可滚动查看。

## 随时切换网页

正式版已经简化过网址输入弹窗，但 `ChatSession.browse()` 仍会因为环境内存在任意 `pending` 记录而拒绝切换网址。ChatGPT 打开普通网站弹出页后，旧回复记录可能属于另一个页面。

2026-11-11 的维护要求进一步明确：回复、文件选择、附件准备、原生任务和独立下载的忙碌状态都不再拒绝用户切换公共网址、打开主页或前进后退。地址表单使用明确的“已接受”结果关闭，不从加载状态或提示文字反推结果；离线时也能接受将要打开的地址。

页面归属由既有导航代次统一管理。新命令使旧页面的读取和观察回调失效，迟到回调不能把旧网址加载回来。页面快照使用 200ms 的尽力保存预算，不依赖网站脚本无限等待。离开原对话时保留发送记录，停止本机对该网页的完成观察；不向服务器发送停止或重发请求。独立下载和原生任务保留自己的生命周期。网页自身的回复连接或上传可能随离开而中断，这不被伪装成后台完成。

网络连接和网页导航分别完成。用户在页面 A 上输入 B 后，界面可能暂时仍显示 A，但 B 已成为本次浏览器选择的目的地。连接准备完成时，只恢复受保护的网络访问，让正在保存快照或等待内核就绪的 B 继续；不会因旧页面仍可见、旧回复记录仍存在，重新导航到 A。连接完成过程中的新操作同样优先，较早的恢复回调不能覆盖后来选择的地址。没有新的浏览器选择时，原有任务恢复顺序继续保留。

断网或切换网络会取消失效的页面捕获和加载队列，但保留用户选择的目的地。网络恢复后使用该目的地重新打开网页，不把已经取消的加载误当作仍在等待的有效命令。离线接受的地址继续显示在地址栏中，重新打开输入框也能查看和编辑它；不会悄悄换回之前的页面地址。停止加载后显示仍保留的实际页面，新发起的历史导航可以接替停止状态。历史导航尚未确认新位置时继续显示当前页面，网站真实跳转、登录重定向和历史提交后再采用内核报告的位置；诊断页仍显示其实际位置，ChatGPT 登录跳转不会被保存为冷启动恢复地址。

点击会话通知也通过同一个网址导航入口认领目的地，再按需连接网络。它不再单独写入另一组等待地址，因此先输入一个网址、随后点击通知时，连接恢复会服从后一次明确选择。

公共网址、环境身份、网络及内核保护继续决定请求能否实际发出。它们不再与“当前有没有回复或文件操作”混在同一个导航许可判断中。

停止加载同时取消当前页面尚未完成的时区导航意图，避免切换弹出页后旧回调重新打开已停止的网址。该操作不重置环境的时区策略或登录数据。

## 旧系统启动兼容

API 32 的实际运行暴露了环境 Context 注册系统回调时的递归。仅将回调注册及注销转交给实际 Application，继续保留 Gecko 的环境应用 Context、独立存储与子进程路由；回归检查同时验证直接转给 ProfileContext 仍会失败，不能用丢失环境隔离的方式修复。

## 验证与范围

当前开发重点是问题修复与维护性整理，暂停新增功能。完整审查与后续拆分顺序见 [浏览器维护审查](MAINTENANCE-AUDIT.md)。维护回归入口为 `tools/browser/check_maintenance.py`，直接编译当前行为并保留故障注入；它不替代完整发布验收。

本轮新增的导航和工具栏行为测试执行生产方法，使用明确的 JVM 边界对象；它们不等同于 Android 实机运行。原生 UI 的 API 编译使用真实 Android SDK。新增 `Browser workspace UI validation` 工作流在同一源码上构建 APK、运行 lint，并继续执行 API 35 与 API 32 的原生截图、阅读、输入、字号、安全区和玻璃验证；原验证工作流保持原样。

已有测试中“点击环境必须停在仪表盘”“ChatGPT 页面必须隐藏地址栏”的产品预期随本次需求更新；环境身份校验、重放保护、草稿保护、原生任务与文件保护继续保留。用于检查仪表盘的测试改从明确的“环境详情”入口进入。

网络标签中的国家或地区仍只来自明确节点名称或保存的标签。测试页面、合成网络配置和演示下载不作为真实 IP、联网、登录或传输成功的证据。正式发布仍需原签名和完整发布验收；本轮不修改更新源。
