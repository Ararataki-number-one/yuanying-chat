# 2.0.1：附件选择与下载列表修复

继续使用单 GeckoView 内核和 ChatGPT 原网页，保留各环境的登录、草稿与入口 / 固定出口配置。安装包沿用原包名和签名，向前覆盖升级。

## 修改范围

- 下载工作区保留原来的页面、滚动容器和文件卡片，只更新有变化的进度与状态；不再按定时器重建整页。
- 进行中的下载优先显示，其余记录按下载时间倒序排列。文件卡片显示已记录的开始 / 保存时间；旧记录没有时间时如实说明。
- 下载期间减少完整历史记录的重复写入；暂停、失败、取消和保存完成继续及时保存关键状态。
- 附件选择使用实际文档状态判断，不再仅因应用的加载标记未结束而静默拒绝。真实换页、旧请求及取消结果仍需正确处理。
- 已显示网页的加载状态超时不再自动触发网络重连或整页加载。同一有效线路的恢复探测暂不可用时保留当前可用页面。

此版本不更改官方网页的输入、发送或消息界面，不改 Gecko SDK 输入补丁，也不启用尚未支持的深层指纹能力。

## 手机重点检查

1. 在原网页添加图片与文本文件，确认选择器出现、文件进入网页并完成上传；取消选择不产生附件或提示轰炸。测试选择器返回后继续输入，以及云盘来源和同名多选。
2. 在下载页滑动列表，等待至少三个刷新周期；屏幕不闪烁、不反复跳回原位置。下载中的卡片在前，进度继续更新。
3. 检查已保存文件的时间与倒序排列；暂停、继续、完成、删除和应用重新打开后，状态与文件内容正确。
4. 保持有草稿或正在回复的 ChatGPT 页面打开，观察加载较慢和前后台返回时是否出现自动刷新、重复登录或草稿丢失。

上述检查补充 [2.0 手机验收清单](PHONE-ACCEPTANCE-v2.0.md)，不能由云端受控网页或测试输入法结果替代。真实账号、百度输入法、ARM 手机和持续使用效果仍以实机结果为准。
